# 기록 체계 안내

이 프로젝트는 "무엇을 만들었는지"뿐 아니라 **어떻게, 왜 그렇게 만들었는지**를 남긴다.
나중에 같은 작업을 반복하거나, AI에게 이어서 작업을 시킬 때 이 기록이 그대로 맥락이 된다.

| 폴더/파일 | 무엇을 적나 | 언제 쓰나 |
|---|---|---|
| [`devlog/`](devlog/) | 날짜별 작업 일지: 목표, 실행한 명령어, 결과, 겪은 문제와 해결 | **작업할 때마다** (하루 1파일) |
| [`decisions/`](decisions/) | 결정 기록(ADR): 선택지, 고른 것, 이유 | 기술·구조를 **결정할 때** |
| [`prompts/`](prompts/) | 다시 쓸 수 있는 프롬프트 모음 | 좋은 프롬프트를 **발견했을 때** |
| [`runbook.md`](runbook.md) | 실행 방법, 포트, 자주 나는 오류 해결법 | 실행 방법이 **바뀔 때** |
| [`structure.md`](structure.md) | 디렉토리 지도: 어떤 파일이 어디서 무슨 일을 하는지 | 폴더·주요 파일이 **생길 때** |
| [`learning/`](learning/) | 학습 로드맵과 단계별 학습 기록, 개념 사전 | 한 단계를 **배울 때마다** |

## 작성 규칙

- **devlog**: 파일명 `YYYY-MM-DD-주제.md`. 명령어는 복사해서 다시 실행할 수 있게 그대로 적는다.
  실패한 시도와 원인도 꼭 적는다. 다음에 같은 문제를 만났을 때 가장 쓸모 있는 부분이다.
- **decisions**: 파일명 `NNNN-주제.md` (번호 증가). 한 번 정한 결정은 고치지 않고,
  바뀌면 새 ADR을 쓰고 이전 것의 상태를 `대체됨(→ NNNN)`으로 바꾼다.
- **prompts**: 템플릿의 바꿔 넣을 부분은 `{{이렇게}}` 표시한다. [`prompts/README.md`](prompts/README.md)에 목록을 갱신한다.
