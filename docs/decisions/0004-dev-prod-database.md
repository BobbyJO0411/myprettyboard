# 0004. 여러 PC 개발: DB는 PC마다, 구조는 git으로 공유

- 상태: 채택
- 날짜: 2026-11-10

## 배경

여러 PC에서 개발을 이어가야 한다. 코드는 GitHub으로 공유하면 되는데, DB는 어떻게 할지 정해야 했다.
처음엔 "DB 하나를 같이 쓰는 게 낫지 않나?"라는 의문이 있었다.

## 선택지

- **A. 개발 DB를 PC마다 따로 + 마이그레이션으로 구조 공유**: 오프라인 가능, 서로 영향 없음, 막 지워도 됨 / 테스트 데이터는 PC마다 다름 (시드 스크립트로 해결)
- **B. 개발할 때도 DB 하나를 공유** (집 서버 + Tailscale, 또는 Neon/Supabase): 데이터가 어디서나 같음 /
  한 PC에서 테이블을 바꾸면 다른 PC 코드가 깨짐, 테스트하다 실수하면 진짜 데이터가 날아감, 서버가 꺼지면 개발 불가

## 결정

**둘을 용도로 나눈다.**

- **개발용 DB = A**: PC마다 Docker로 띄운다. 테이블 구조는 Alembic 마이그레이션 파일(`server/migrations/`)로 git에 올려 공유한다.
- **운영용 DB = 한 곳**: 실제로 쓰는 데이터(할 일, 블로그 템플릿 등)는 24시간 켜진 서버 한 곳에 둔다. 서버 위치가 정해지면 구성한다.

비유: 집마다 **연습용 주방**(개발 DB)을 두고, **주방 배치도**(마이그레이션)와 **레시피**(코드)만 GitHub으로 공유한다.
진짜 손님을 받는 **식당 주방**(운영 DB)은 한 곳이다.

## 이유와 영향

- 새 PC 세팅은 `scripts/setup.ps1` 하나로 끝나게 만들었다.
- 테이블을 바꿀 때는 **반드시 마이그레이션 파일을 만들고 커밋**해야 한다. DB를 손으로 직접 고치면 다른 PC와 어긋난다.
- 다른 PC에서도 같은 테스트 데이터가 필요해지면 시드 스크립트를 추가한다. (첫 모델이 생길 때)
